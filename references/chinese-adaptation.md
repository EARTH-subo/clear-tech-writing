# STE 纪律的中文适配（ZH 模式）

> ASD-STE100 没有官方中文版，中文也没有官方受控语言标准。本文件是把 STE 纪律映射成中文的适配层。
> 分级、阈值与中文特有规则参考了 STC 0.2（mzopedia，CC BY 4.0）、asd-ste100-skill-zh（lemonhall）、
> zh-ste100-jev-skill（KonglingDaDa）、ste-zh（dualface）、Tech-Doc-Style-Chinese（Fenng）、
> tech-writing-style（mrtsels）。逐项来源见 `sources.md`。
>
> 输出侧不出现"符合 ASD-STE100""已合规"这类声明。对外称"STE 风格的中文适配"。

## 0 使用前提

**三种句子**
- 操作句：要求读者执行动作，通常在编号步骤里，动词开头。
- 描述句：说明对象、状态、原理。
- 汇报句：说明"做了什么、成了没、为什么"。

**两个级别**
- 【必须】：违反即不合规，改写时必须处理。
- 【建议】：违反只提醒；处理会损失信息或自然度时保留，并向用户说明。

**字数口径**：汉字 1 字计；标点不计；英文词、数字、数字 + 单位各计 1；代码与表格单元格不计。

**档位对应句长**

| 档位 | 单句上限 | 依据 |
|---|---|---|
| report 汇报 | 35 字 | 开源文档正文 p90 为 41、本地为 36，取两者之间偏紧 |
| procedure 步骤 | 30 字（安全关键 25）| 开源 p90 为 31、本地为 35；取 30 比开源九成线略紧 |
| descriptive 说明 | 40 字 | 开源 p90 为 41、本地为 36；取 40 与开源九成线基本重合 |

## 1 字法：词

- 【必须】一个概念全篇一个词，不为避免重复换同义词（用户 / 客户 / 使用者 只留一个）。
- 【必须】用具体动词，不用虚动词包装：写"修改配置"，不写"对配置进行修改"。禁用"进行 / 加以 / 作出 / 予以 + 动词"。
- 【必须】不用没有数值的程度词：很、非常、较、比较、大量、少量、尽快、及时 → 写数值、范围或条件。
- 【必须】不用行业黑话与伪术语：赋能、抓手、闭环、拉通、打通、沉淀、落地、对齐、收口、颗粒度、组合拳、顶层设计、底层逻辑。
- 【必须】不用零信息套话：需要注意的是、值得一提的是、众所周知、其实、事实上、不难看出、总的来说、简单来说、在一定程度上、希望对你有帮助。
- 【必须】不用伪抽象评价：具有很高的可读性、具备良好的可用性、实现了……的自动化 → 写可测的事实。
- 【必须】中文特有的一词一义按下表执行。
- 【必须】缩略语首次出现写全称，之后固定一种写法。
- 【建议】有通行中文译名的术语用中文，首次出现括注英文；同一术语不中英混用。

### 中文特有的一词一义

| 词 | 只表示 | 别的意思用 |
|---|---|---|
| 可以 | 允许 | 能力用"支持"（支持 PNG 格式）|
| 打开 | 文件、窗口、页面 | 功能用"启用"，程序用"启动" |
| 关闭 | 文件、窗口、页面、连接 | 程序用"停止"，编辑器用"退出" |
| 以上 / 以下 / 以内 | 不在数字后使用 | 大于、不小于、不超过 |
| 错误 | 返回的错误结果或错误码 | 组件不工作用"故障"，代码缺陷用"缺陷"，抛出的对象用"异常" |
| 检查 / 验证 / 确认 | 分别是"看有没有问题 / 用测试确认 / 执行前核实条件" | 不互换 |
| 登陆 / 帐号 / 缺省 / 阀值 / 布署 / 报错（名词） | 不批准 | 登录 / 账号 / 默认 / 阈值 / 部署 / 错误 |

## 2 句法：句

- 【必须】句长按档位（第 0 节）。超了先删冗余词，再拆句。
- 【必须】一句只说一件事；分号连接的分句算同一句，要拆。
- 【必须】操作句用祈使句、动词开头；不写"请""您""用户可以""需要"。
- 【必须】主动句，写出执行者。被动只用于执行者未知或不重要的描述句。"被 / 由 / 受到 / 遭到 / 为……所"都算被动标记。
- 【必须】条件写在动作前面，不放句尾，不放括号。
- 【必须】一句最多一个否定，否定词紧挨被否定的动作；不用"不得不""无不""没有……不"。
- 【必须】单句"的" ≤ 2 个，定语 ≤ 15 字，超了拆句。用动宾小句做主语，不用"名词 + 的 + 动作"做主语。
  - ✗ 由于接口的调用失败导致了那个在非仓库目录下的配置加载的中断
  - ✓ 调用接口失败，配置加载中断
- 【必须】剥掉欧化介词壳：基于……的情况下、在这种……配置下、针对……问题、对于……而言、由于……所导致的。直接说主语和动作。
- 【必须】指代只指紧邻上一句的对象；跨句就重复名词。"相关"不作指代。
- 【必须】不用反问、设问、感叹。
- 【建议】描述句写出主语，尤其系统和人都可能是执行者时：点击"保存"后，系统重新加载配置。
- 【建议】并列成分用相同结构：创建用户、删除用户和修改权限。

## 3 段与列表

- 【必须】一段一个主题，第一句点明主题；≤ 6 句。
- 【必须】步骤用编号列表，并列事项用项目符号；不在正文用"首先 / 然后 / 最后"串联步骤。
- 【必须（程序档）】不用"等""之类"结尾的开放列举：列全，或写数量并用"包括"；描述句可以用"例如"。
- 【建议（说明 / 汇报档）】原话本身不穷尽时保留"等"。删掉"等"等于断言列举完整，属于改原意。
- 【建议】同一列表各项结构一致（全句子或全短语，全动词开头或全名词开头）。

## 4 步骤与警告

- 【必须】一步一个动作；只有真正同时发生才用"同时"合并。
- 【必须】区分人的动作与系统的行为：人的动作写祈使句，系统的行为用"系统"或组件名作主语。
- 【必须】警告放在它针对的步骤之前，独立成段；只写危险、后果、怎么避免，不写操作步骤。
- 【必须】前置条件单独列出放在步骤之前，不塞进括号。
- 【建议】预期结果另起一句写在动作后：点击"测试连接"。系统显示"连接成功"。
- 【建议】步骤里不解释原因；原因放前面的说明段，或步骤后以"说明："开头。

## 5 汇报（report 档专用）

技术文档正文不套这一节；只用于对用户说"做了什么、成了没、为什么"。

- 【必须】首句给结论：成了 / 没成 / 卡在哪 / 根因是什么。禁"基本上""应该已经""大概""似乎"这类太极词。
- 【必须】状态词只用这 10 个：已完成、部分完成、未开始、进行中、已验证、未验证、失败、跳过、阻塞、未确认。写状态必须带范围。
- 【必须】工作状态与验证状态分开。"已完成"不表示"已验证"。
- 【必须】如实写验证：写清检查方法、结果、覆盖范围。没跑写"未验证"；缺证据写"未确认"并写确认方法。
- 【必须】证据可定位：代码给 `路径:行号`，提交给提交号，命令给完整命令。
- 【必须】不叙述过程：不写"我先……然后……接着……"。
- 【必须】不编造：来源没有的事实不补，缺的进"待确认"。
- 【建议】要用户决定时列编号选项，每项写动作和后果，推荐项放第一并标"（推荐）"。

## 6 标点、数字与时间

- 【必须】标点按 GB/T 15834-2011，中文语境用全角；不用分号串联完整论断（对应英文 8.1）。
- 【必须】数字按 GB/T 15835-2011；阿拉伯数字与单位之间空一格；百分号紧跟数字。
- 【必须（程序档）】范围写明含不含端点：写"大于 10"或"不小于 10"；含端点写"3 至 5（含）"。
- 【建议（说明 / 汇报档）】原文写"10 以上"时，先确认含不含端点。无法确认就保留原话，不替作者改判。
- 【必须】不用相对时间：明天、下周、近期、稍后 → 绝对日期或时长。
- 【必须】倍数与百分比固定写法：减少不用"倍"，写"减少到原来的 1/3"；百分比下降用"个百分点"。
- 【必须】界面元素名用「」括起，与界面文字完全一致；代码、命令、路径、字段名原样保留，不翻译、不改大小写。
- 【必须】中英混排时英文词、数字与中文之间加空格。
- 【建议】时间用 24 小时制；面向跨时区读者注明时区。

## 7 保真底线（改写不能碰的东西）

- 不改情态：可能 / 也许 / 通常 / 建议承载作者给的置信度，是内容不是修饰。把"可能已失败"改成"失败"，等于换了一个结论。
- 不改数字、单位、范围、条件、例外、默认值、失败处理。
- 不加原文没有的原因、频率、机制、预期结果。
- 原文本来就合规，直说合规，不硬改。
- 内容本身是空话，改完只会变成一段干净的空话——直说，不粉饰。
- 为短而删掉安全条件、范围限定时，必须标注这个取舍。

## 8 与英文 STE 的对应关系

| 英文 STE | 中文对应 |
|---|---|
| 25 / 20 words（5.1–5.3、6.1–6.6） | 35 / 30 / 40 字（汇报 / 步骤 / 说明）。按中文句长分布单独校准，不是字数换算 |
| 主动语态、祈使句（3.6） | 主动句写执行者；操作句祈使、动词开头、不带"请 / 您" |
| 不用短语动词（9.3） | 中文无短语动词，对应禁"进行 / 加以 / 予以 / 作出 + 动词" |
| 动作用动词不用名词化（3.7） | 直接用动词，不写"……的实现 / ……的进行 / 做出调整" |
| -ing 只作技术名词（3.5） | 不把动词当形容词或名词用（"运行的发动机"→"处于运行状态的发动机"） |
| 名词串 ≤ 3（2.1） | 单句"的" ≤ 2 个，定语 ≤ 15 字 |
| 不省主语、谓语、冠词（Section 4） | 操作句省主语，描述句写主语；数量词、谓语不省 |
| 分号禁用（8.1） | 分号不使用，拆句 |
| 同义词选一（1.11、9.4） | 同义选一；中文特有"可以 / 支持""打开 / 启用 / 启动"按义分开 |
| 时态限简单时态（3.2） | 不叠用"曾经 / 将要 / 一直"；体标记（已经……了）只在承载当前相关性时保留 |
| 词典约 900 词（1.1–1.4） | 中文无受控词典 → 只对高频词做一词一义，其余靠"常用词优先、术语一致、虚词克制" |
| 三级安全提示（Section 7） | 相同：警告 / 注意 / 说明；警告只写危险、后果、规避 |
| 词数计数口径（8.6） | 按第 0 节的字数口径 |

## 9 边界

- 本文件是适配层，不是中文标准，不能作为"合规"依据；也不暗示与 ASD 有任何关系。
- 可机械检查的：句长、分号、虚动词、禁用词、相对时间、数字后"以上 / 以下"、单句"的"数量。只能人工判断的：定语是否过长、指代是否清楚、术语选得对不对、逻辑顺序、情态是否被改弱。不要把后者写成硬勾。
- 与"去 AI 味"类改写互斥：STE 成品是故意平淡、字面化的，追求语气与节奏时不要用本模式。

## 10 语料校准

**两批语料**

| 批次 | 来源 | 规模 | 步骤 p90 | 符号 p90 | 正文 p90 |
|---|---|---|---|---|---|
| A 本地 | 作者本人的中文技术文档 | 211 文件 / 68.5 万字 / 4.06 万句 | 35 | 39 | 36 |
| B 开源 | kubernetes/website、ant-design、pingcap/docs-cn、rust-lang-cn/book-cn、mdn/translated-content | 46 篇 / 10.8 万字 / 6431 句 | 31 | 24 | 41 |

**交叉验证**：开源语料的正文 p90 为 41，与 STC 公布的 41 完全一致；步骤 31 与其 33 接近。说明 STC 的校准方法在独立语料上可复现。

**结论**：30 / 40 保持不变。
- 只按本地语料看，40 偏松（本地 p90 只有 36）；加入开源语料后，40 正好压在九成线上。**单批语料会得出错误结论。**
- 步骤 30 在开源语料上命中断面约 11%，属于有意收紧，因为步骤读错的代价高于描述句。

**复现**：`python scripts/calibrate.py <目录>`。换语料必须重跑，不能直接引用上面的数字。

**局限**：开源样本偏小（编号步骤仅 84 句，只能看趋势）；其中 Rust 书与 MDN 是译文，译文句长天然偏长。本地样本偏 AI 生成，句子天然偏短。两批都有方向性偏差，所以取两者之间做判断。
